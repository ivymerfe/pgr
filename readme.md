# pgr

![logo](assets/logo.png)

Инструмент для захвата, воспроизведения и сравнения трафика PostgreSQL.

Читает трафик из `.pcap` или своего формата `/acap`. Может проиграть его на другую базу и сравнить два захвата между собой. Перехватывает пакеты через eBPF.

## Установка

Бинарники: [GitHub Releases](https://github.com/ivymerfe/pgr/releases).

Или собрать из исходников:

```bash
cargo build --release
```

## Команды

### `capture` — записать трафик

```bash
pgr capture -i eth0 -p 5432 -o captures/session1
```

Слушает интерфейс `-i` на порту `-p` и пишет в папку `-o`. Захват разбивается на чанки, при превышении `--max-chunk` (по умолчанию 64MB) начинается новый файл.

Полезные флаги:

- `-l` — уровень сжатия zstd (по умолчанию 3)
- `--zw` — число потоков сжатия
- `-c` — с какого номера чанка начинать (для дозаписи в существующую папку)

### `replay` — воспроизвести захват

```bash
pgr replay captures/session1 -h 127.0.0.1 -p 5433 -d mydb -u postgres
```

Читает захват (папку `acap` или файл `.pcap`) и проигрывает трафик заново на указанный сервер. Соответствие адресов из захвата новым соединениям сохраняется в `--addr-map` (по умолчанию `replay.csv`) — это нужно для последующего `compare`.

### `dump` — выгрузить в CSV

```bash
pgr dump captures/session1
```

Разбирает захват и сохраняет читаемый CSV рядом с исходным файлом (или по указанному пути).

### `compare` — сравнить два захвата

```bash
pgr compare captures/session1 captures/session2 --addr-map replay.csv
```

Сравнивает трафик из двух захватов (например, оригинал и результат `replay`), используя карту адресов, полученную на шаге `replay`. Можно сохранить различия в файл через `-d`.

## Формат `.acap`

Захват сохраняется в папку:

- `map` — список адресов участников соединения, по одному на строку
- `0`, `1`, `2`, ... — чанки данных, возможно сжатые zstd (`.zst`); при заполнении текущего чанка (`--max-chunk`) начинается следующий
